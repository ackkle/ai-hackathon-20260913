# リザーブマシン MVP仕様書 — メンバーA案

- チーム：AIハッカソン・チーム15
- 作成日：2026年9月13日
- 位置付け：ユーザーとの対話をもとにした個人案。チームの正式仕様ではない。
- 想定：3人で開発するスマホ対応Webアプリ。技術構成と利用可能時間は統合時に決定する。

## 1. コンセプト

**仕事がなくても、明日が楽しみになる。**

リザーブマシンは、小さな「やってみたい」を、生きがいにつなげるアプリ。仕事の有無にかかわらず、生きがいがあり、毎日を楽しみにできる人を増やすことをミッションとする。

「10年後、AIによって働く必要が減り、自由な時間が増えたら」という未来を想定する。予測の断定ではなく、ハッカソンの課題設定である。仕事が作っていた予定・役割・つながりを失っても、本人の楽しみを見つけ、日々の体験として育てられるよう支援する。

機能の判断基準は、**「この人が明日を楽しみにできるか？」**。生産性や行動量で人の価値を測らない。「不要な人間」「堕落」といった表現をユーザー向け画面・AI出力・発表に使わず、動けない日や休む選択を尊重する。

長期的には趣味・上達・暮らし・お金など幅広い願望に伴走する。今回のMVPは、1つの願望と1週間・最大3行動に絞り、**予定を決める → 実行結果と気持ちを記録する → 次の予定を調整する**という一巡を実現する。

願望がまだない人は「明日、少し外に出たい」のような過ごし方を仮の目標にできる。最初の成功は、一生の趣味を決めることではなく「明日、ちょっとやってみたいことができる」こと。

### 壁打ちとの違いとして実装する価値

AIとの相談で得られる助言に加え、アプリが目標・予定・実行履歴を保存し、開くたびに「次に何をするか」「どこまで進んだか」を表示する。振り返りの結果を次の提案に引き継ぐため、毎回状況を説明し直す必要がない。比較対象は単発の会話体験であり、特定のAI製品で同様のことが不可能だとは主張しない。

## 2. 対象者と解決する課題

### 中心ペルソナ：仕事が毎日の予定と役割を作ってくれていた人

佐藤さん、48歳（架空の人物・仮設定）。年齢や性別より、仕事中心だった生活背景を重視する。

| 項目 | 設定 |
| --- | --- |
| これまで | 事務職として、任された仕事を日々きちんとこなしてきた |
| 生活 | 特定の趣味はなく、休日は動画や家事で過ごす |
| 変化 | AIによって仕事が減り、自由な時間が増えた |
| 困りごと | やるべきことがなくなり、何をして過ごせばよいか分からない |
| 本音 | 「夢中になれるものがほしい。でも、自分が何を好きなのかも分からない」 |
| 始められない理由 | 選択肢が多く、未経験で気後れし、続かなかったらと思うと動けない |
| 欲しい変化 | 朝起きたときに、少し楽しみにできる予定がある |

### 2つの入口で支援する

| 対象者 | 困りごと | 利用後の状態 |
| --- | --- | --- |
| やりたいことがある人 | 始め方や上達の道筋が分からず、続けられない | 予定と進捗が見え、実行結果に合う次の一歩が決まる |
| やりたいことを探している人 | 趣味を選べず、試しても続け方が分からない | 1つ試し、気持ちを振り返って次の行動を調整できる |

完成時に提供する価値は、自分で選んだ行動を予定にし、実行できた日もできなかった日も次の一歩につなげること。願いの実現や上達速度を保証するものではない。

## 3. MVPの主要機能（3つ）

### ① 願望の入力・発見

最初に「やりたいことがある」「やりたいことを見つけたい」の2つから選ぶ。

- ある人：願望を自由入力し、経験・使える時間・予算を回答する。
- 探す人：最初に「明日を、どんな日にしたいですか？」と聞き、「少し外に出たい／誰かと話したい／何か作ってみたい／ゆっくり休みたい／まだ分からない」から選ぶ。明確な願望や趣味の入力を必須にしない。
- 使える時間・予算を回答すると、AIが試せる体験を3つ提案する。趣味名だけでなく「10分歩いて気になったものを1枚撮る」のような最初の行動を示し、本人が1つ選ぶ。経験は未経験を初期値として変更できる。
- 「まだ分からない」の場合も、負担の小さい異なる体験を3つ提示する。AIが好みを断定せず、本人が試すものを選ぶ。
- 回答は選択肢を中心にし、自由記述を補助として使う。「分からない」「特にない」も選べる。
- 体験の候補は、名前・回答に対応する提案理由・最初に試すことを表示する。「まず1回試す」選択として提示する。
- 候補が合わなければ条件を編集して再提案できる。

### ② 最初の1週間の行動とスケジュールを管理

- AIが、本人の条件に合う「目指す状態」と、今後7日間で試す行動を最大3件提案する。
- 各行動に、内容・所要時間・必要な準備を付ける。
- 初心者がいきなり成果を出すことを前提にせず、探す・試す・振り返るなど実行できる粒度にする。
- 「目指す状態」と「自分がやりたい理由」は本人が編集できる。AIの推測を本人の回答として扱わない。
- やりたい理由の記入は任意。「まだ分からない」でも予定を作れる。休む体験も予約でき、上達目標や成果を必須にしない。
- 使える曜日・時間帯を入力し、AIが日時候補を提示する。本人が各行動の日時を調整して確定する。未設定の行動は「日時未設定」と表示する。
- 確定した行動は予約票として発券し、ホームの週間リストに日時順で表示する。日時未設定の行動は別に表示する。
- 予定の日時変更・見送りができる。アプリ内の予定が重なる場合は確定前に知らせる。外部カレンダーの空き状況は取得しない。
- 次の予定をホーム上部に表示する。時刻を過ぎた予定は「振り返り待ち」とし、自動で失敗扱いにしない。
- 「予約」は本人の行動予定の確定を意味する。店舗・教室・相手への予約や連絡は行わない。

### ③ 進捗・気持ちの振り返りと次の一歩の調整

- 行動ごとに「できた／少しできた／できなかった」と「楽しかった／ふつう／しんどかった／回答しない」を記録する。「またやりたい／別のことを試したい／まだ分からない／回答しない」も任意で選べる。理由や感想の一言は任意。
- ホームの中心は「次の楽しみ」と、本人が記録した「楽しかった体験・またやりたいこと」。完了件数・少しできた件数・残りの予定は補助情報として表示する。行動件数を上達率・生きがい・幸福度の点数に換算しない。
- AIが目標・直近の実行結果・本人が入力した気持ち・再体験の希望を読み、短いフィードバックと次の行動案を1件返す。
- 楽しかった体験は次の楽しみに育てる。合わなかった場合は継続を強要せず、別の小さな体験を提案する。休みたい場合は休む予定も候補にする。
- できた場合は小さな前進を認める。できなかった場合は責めず、短くする・日程を変える・休むなど状況に合う案を提示する。
- 本人が承認した場合だけ、対象の未完了行動を更新、または残り枠に1件追加する。現在の行動枠は最大3件。満杯なら未完了行動の置き換え対象を選ぶ。変更しない選択もできる。
- 振り返りと予定変更の履歴を保存する。日程を変えても、過去の実行結果を消さない。
- 最大3件がすべて完了・見送りの場合は、履歴を残して次の1週間の計画を作れる。新しい計画も最大3件とし、前の計画の感想を提案に引き継ぐ。

## 4. 画面と操作の流れ

| 画面 | 表示・入力する内容 | 主な操作 |
| --- | --- | --- |
| 入口 | コンセプトと2つの入口 | ある／見つけたいを選ぶ |
| 条件入力 | 願望または明日の過ごし方、時間、予算、必要に応じて経験 | 提案を作る |
| 体験候補（探す人のみ） | 試せる体験3候補と提案理由 | 1つ選ぶ／条件を直す |
| 行動案 | 目指す状態、やりたい理由、最大3件の行動 | 内容と日時を調整して予約 |
| ホーム | 次の楽しみ、今週の予定、楽しかった体験、実行件数 | 予約票を開く／日時変更／振り返る |
| 予約票 | 確定内容、予約番号、始めるための言葉 | 予定を編集／見送る／振り返る |
| 振り返り | 実行結果、気持ち、またやりたいか、任意の一言、AIの調整案 | 記録／次の案を承認または保留 |

共通の流れ：願望 → 簡単な質問 → 行動案 → 予約 → 実行結果と気持ちの記録 → 次の予定の調整。再訪時は保存されたホームを開く。

## 5. 予約票の内容とマインド面の支援

| 項目 | 表示例 |
| --- | --- |
| 予約番号 | RM-20260913-001（形式例。実装では重複を避ける） |
| やりたいこと | 明日、少し外に出てみたい |
| 自分の理由 | 気分を変えてみたい（本人の入力例。未回答なら表示を省略） |
| 今回の一歩 | 10分歩いて、気になったものを1枚撮る |
| 日時・所要時間 | 2026年9月14日 10:00〜10:10・10分 |
| 場所 | 自宅の近所 |
| 準備 | スマートフォン、歩きやすい靴 |
| 気が重いときは | 玄関の外で空を1枚撮るだけでもOK |
| 始める言葉 | 上手に撮る必要はありません。気になったものを1つ。 |

マインド面は予約票と振り返りに組み込む。気持ちに応じて励ましだけでなく行動の負担も調整する。未実行を責める表現や成功の断言はしない。本人が気持ちを回答しない場合は推測しない。対象は日常の意欲と継続の支援であり、診断・治療は機能に含めない。

## 6. AIと本人の役割

| AIが提案すること | 本人が決めること |
| --- | --- |
| 趣味の候補と理由 | 何を試したいか |
| 現状に合った目標の案 | 目指したい状態・自分の理由 |
| 最大3件の行動と準備 | 実行する行動・日時・予約の確定 |
| 小さな代替行動と始める言葉 | 提案を採用するか、変更するか |
| 振り返りを踏まえた負担・日程の調整案 | 実行結果と気持ちの記録、予定変更の承認 |

生成時の共通ルール：

- 回答された時間・予算・経験に合わせる。不明な情報は確定情報として扱わない。
- 行動量や継続を人の価値に結びつけない。休む・別のことを試す選択を尊重し、本人の「楽しかった」「またやりたい」を次の提案の手がかりにする。
- 実在施設の空き状況・料金・他人の参加承諾を作り上げない。未確認の場所は候補として扱う。
- 「お金持ちになりたい」など広い願望には、目的を具体化し、学習や現状整理などの最初の行動を提案する。利益や達成を保証しない。
- スポーツでは経験に合う小さな一歩を提案し、個別の診断や無理な運動指示を行わない。
- 実現が難しい願いも一方的に否定せず、背景にある希望に近い体験を候補として提示する。

## 7. MVPの実装方針（統合時に技術選定）

- スマホとPCで使うWebアプリ。ログインは不要。
- AIの呼び出しはサーバー側で行い、APIキーをブラウザに渡さない。
- 体験候補・行動案・振り返りへの提案は構造化データで受け取り、アプリ側で必須項目・件数・日時を検証する。
- 生成中は処理中の表示を出し、二重送信を防ぐ。
- 生成失敗や形式不正では入力を保持し、再試行できる。成功したような予約票は表示しない。
- 日時は日本時間。相対表現は実際の日付にし、確定前に表示する。過去日時は確定できない。
- 目標1件・現在の行動最大3件・予約票・振り返り・変更履歴をブラウザのローカル保存領域に保存し、再読み込みで復元する。端末間同期はしない。
- 新しい目標を作るときは現在の目標と履歴が置き換わることを確認する。設定から記録を全削除できる。
- 保存に失敗した場合はその旨を表示し、画面上の入力と記録は残す。
- 振り返り自体を先に保存してからAIに調整案を求める。AIが失敗しても記録は残り、既存予定を変更しない。
- 行動は安定したIDで管理する。状態は「未予約／予定あり／できた／少しできた／できなかった／見送り」。日時経過による「振り返り待ち」は表示上の区別とする。
- 再予約時は同じ行動IDで予定を更新し、前の日時と振り返りを履歴に残す。過去の記録の二重送信を防ぐ。完了件数は現在の行動枠の状態から集計する。

最低限のデータ：入口の種類、願望／希望する過ごし方、経験、利用可能な曜日・時間帯、予算、選んだ体験、目標、本人の理由（任意）、計画ID、各行動のID・状態・開始日時・所要時間・準備・場所・代替行動・始める言葉・予約番号、実行結果・気持ち・再体験の希望（任意）・任意メモ・記録日時、変更前後の予定と承認日時。過去の計画も同じ目標の履歴として保存する。

## 8. 今回は作らないもの

- 複数目標の同時管理、長期の上達分析、習慣化の統計
- 本人の承認なしの予定変更、通知、継続チャット
- 店舗・教室の実予約、決済、他人への招待
- Googleカレンダーとの認証・同期
- アカウント、クラウド保存、端末間同期

余裕があれば、予約票のカレンダーファイル（.ics）出力を追加する。必須機能の完成を優先する。

## 9. 完成条件

- 「ある」入口から、入力→行動案→日時選択→予約票まで進める。
- 「見つけたい」入口から、「まだ分からない」でも体験3候補→選択→行動案→予約票まで進める。
- 行動案は最大3件で、本人が確定した日時が予約票と週間リストに正しく反映される。
- 予約票に準備・小さな代替行動・始める言葉が表示される。
- 「ある」入口の空欄の願望、または候補画面での未選択では先に進めず、過去日時を確定できない。「見つけたい」入口では明確な願望や理由がなくても進める。
- AIのエラー時に入力が消えず、再試行できる。
- 日時変更が次の予定表示に反映され、重複する予定には注意が表示される。
- 実行結果と気持ちを記録でき、完了・少しできた件数が正しく更新される。
- 「できなかった・しんどかった」の記録から、負担を小さくする次の案を提示できる。
- 「楽しかった・またやりたい」がホームと次の提案に反映され、未回答の感情は推測されない。
- 「別のことを試したい」や「休みたい」を選べ、継続を強要せず次の案を提示できる。
- 全件完了・見送りから次の計画へ進んでも、前の計画の実行結果と感想が残る。
- 調整案は承認前に予定を変更せず、承認後にのみ反映される。変更前の履歴は残る。
- 振り返り後のAIエラーでも記録が残り、再試行できる。
- 再読み込み後に目標・予定・振り返り・変更履歴が復元され、記録の全削除もできる。
- スマホ幅で入力から発券・振り返り・調整まで操作できる。
- 実際に行っていない手配を「予約済み」と表示しない。

## 10. デモ例

### A：やりたいことがある

「テニスが上手くなりたい」→ 未経験・週末1時間・予算3,000円 → 初心者向けの最初の行動 → 教室を探す日時を本人が決定 → 予約票。

### B：中心ペルソナの体験（発表の入口）

佐藤さんは趣味も願望も思いつかない。「明日を、どんな日にしたいですか？」に「少し外に出たい」と回答 → AIが3候補 → 「10分歩いて1枚撮る」を選ぶ → 明日10時の予約票 → 「楽しかった・またやりたい」を記録 → 次は別の道を歩く案が出る。趣味が決まる前でも、明日の楽しみが作れることを示す。

候補や文面は例であり、実際のAI出力と一致する必要はない。条件に合った行動へ進めることを確認する。

### C：実行できなかった後も伴走する（発表の中心）

デモ用と明示した実行前後のサンプルを用意する。「10分歩いて1枚撮る」予定に「できなかった・しんどかった」と記録 → AIが「玄関の外で空を1枚撮る」案を提示 → 本人が翌日の空き時間を選んで承認 → 次の予定が更新される。休む選択もでき、記録が残ることを確認する。

発表の一言：**「仕事がなくても、明日が楽しみになる。小さな『やってみたい』を、生きがいにつなげます。」**

体験の確認では「明日やってみたいと思えたか」「負担なく始められそうか」「また使いたいか」を本人に聞く。短時間のデモで長期的な生きがいの改善を実証したとは扱わない。

## 11. 3人の担当案と進め方

| 主担当（仮） | 開発範囲 | 提出・発表に向けた仕事 |
| --- | --- | --- |
| ① 体験・画面 | 入口・条件入力・体験候補・振り返り入力 | 紹介動画の構成・録画・編集 |
| ② AI・機能 | 初回提案と振り返りのAI処理、出力検証、失敗時の処理 | デモ用入力、生成品質の確認 |
| ③ 統合・公開 | 週間リスト・予約票・進捗・予定変更・保存、全体接続とデプロイ | 提出物と発表資料の取りまとめ |

個人仕様書のA・B・Cと担当番号は対応しない。得意分野を確認して配属し、③に負荷が集中したら画面実装や資料作成を分担する。発表者は説明が得意な人を選び、企画の判断役とあわせてチームで決める。

開発前に3人で画面間のデータ形式を固定する。最初は固定サンプルデータで画面をつなぎ、その後AI処理に置き換える。動作確認と発表準備は全員で行う。

4時間の場合の配分例（実際の残り時間と大会の提出条件に合わせて調整）：

| 時間 | 到達する状態 |
| --- | --- |
| 0〜30分 | 3案を統合し、必須機能・担当・データ形式を決定 |
| 30〜60分 | 仮画面をデプロイし、全員が同じURLを開ける |
| 60〜150分 | 分担して実装、サンプル接続からAI接続へ。動画構成と発表骨子も準備 |
| 150〜180分 | 公開URLで予約→振り返り→予定調整が動く |
| 180〜210分 | 機能追加を止めて修正、安定した画面で動画録画 |
| 210〜240分 | 発表練習、公開URL・動画・提出物を確認 |

小さなPull Requestをこまめに取り込み、同じファイルを同時に変更する担当を事前に調整する。デプロイを最後まで待たない。

### 提出物と発表の完成条件

- 公開URL：別の端末でも2つの入口と伴走の一巡が動く。AIキーはサーバー側に設定する。
- 紹介動画：佐藤さんの困りごと→体験の予約→振り返り→次の提案を見せる。大会指定の長さ・形式に合わせ、サンプルはデモ用と明示する。
- 発表：未来の課題、中心ペルソナ、実演、予定・履歴を引き継ぐ価値、今後の展開の順で説明する。動画と同じ人物・体験例を使う。
- 発表時の接続不良に備え、録画を手元でも再生できる状態にする。
- アプリ・動画・資料の内容が実装済み機能と一致し、未来の構想は区別されている。

チームの完成は「アプリが動く」に加えて「公開URL・紹介動画・発表が揃う」こと。

予約票だけの案より実装量が増える。時間が足りない場合は画面の演出・カレンダー出力・候補の再生成を先に削る。「予約→振り返り→次の予定の調整」は本案の価値として優先する。

## 12. 統合時にチームで決めること

これは本案の不足を埋めるためではなく、3案から正式仕様を選ぶための判断事項。

- 中心ペルソナと「明日が楽しみになる」というミッションの採用
- 2つの入口を両方実装するか
- 目標1件・現在の行動最大3件で伴走の一巡を見せる範囲
- 週間リスト・進捗・気持ちの振り返り・承認付き予定調整を中心にするか
- 使用技術、AIサービス、実際の残り時間、各自の担当
- デプロイ先、大会の動画・発表・提出条件、発表者
