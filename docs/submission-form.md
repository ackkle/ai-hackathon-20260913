## 誰の、どんな困りごとを、どう変える作品ですか？

```
定年、週休3日、AIによる業務の減少、就活の終了。自分で選んだわけではない空き時間が降ってきて、やる気がないのではなく、やる気を仕事に使い切ってきたから、その時間に何をしたいかが自分でも分からない人が対象です。リザーブマシンは、その曖昧な気持ちを日時と準備の入った1枚の「予約票」に変え、やってみた後の振り返りから次の一歩を決めるところまでを扱います。
```

## 「10年後のあたりまえ」と、どうつながりますか？

```
10年後、空いた時間は一部の人に起きる事件ではなく、ほとんどの人の前提になっていると考えています。そのとき「その時間で何をするか」を決める道具が、カレンダーと同じくらい日常のものになっているのが、この作品の見ている「あたりまえ」です。今回はその全体を、10年後の暮らしから今週の1件まで降りてくる22画面の流れとして設計し、そのうち逆算ツリーからカレンダー、振り返りと次の一歩までの7画面を動かしました。
```

## 未完成の部分・アクセス条件・注意点

```
動くのは7画面（逆算ツリー、日時決定、予約票、カレンダー、ホーム、振り返り、次の一歩）と、この端末内への保存です。残り15画面は「サンプル：画面の準備中です」または「構想デモ（実際のデータではありません）」の帯つきの雛形で、公開版のAIは固定のサンプル応答（モック）で動いています。

カレンダーは、Googleカレンダーの入力画面を開くテンプレートURLの方式だけ動きます。予定ファイル（.ics）とAPIによる自動登録は未実装です。アプリはカレンダー側の保存を確認できないため、本人が「カレンダーに保存した」を押すまで「未登録」と表示します。統計の参照値と相談先の案内は、偽の情報になるため動くまで機能ごと隠しています。

ログイン・課金・特定の機器は不要です。記録はブラウザのlocalStorageにのみ保存し、サーバーには送りません。金額の表示はすべて目安です。
```

## 今回作った部分と、独自の工夫

```
今回作ったのは、22画面の遷移設計、日時決定から予約票までの予約ロジック（過去日時は確定させない、重なりは警告して本人に返す）、振り返りと次の一歩、localStorageの保存契約、AI出力をzodスキーマと表現の検査（人を評価する言葉・断言・強要を通さない、金額に「目安です」を付ける）に通してから画面に出す呼び出し層です。土台はNext.js、OpenNext、Cloudflare Workers、各社のSDKです。

工夫は、「動いていないものを動いているように見せない」を設計の中心に置いたことです。たとえばカレンダーは、アプリ側から保存を確認できないので、入力画面を開いただけでは「未登録」のままにし、本人が保存したと押したときだけ登録済みにします。未完成の画面は消さずに「サンプル」の帯つきで残す一方、偽物が人を誤解させるもの（統計の数値、相談先の案内）は機能ごと隠す、という線引きを、コードの機能モード（本実装／簡易実装／モック／構想デモ／非表示）で固定しています。

コード：https://github.com/ackkle/ai-hackathon-20260913
仕様：docs/specs/mvp-spec.md
```

## AIを何に使い、どのように役立ちましたか？

```
制作では、3人が別々に書いた仕様書3本をClaude Codeに読ませて矛盾を10項目に洗い出させ、「10年後と1年後のどちらを軸にするか」「反対役を入れるか」といった判断は人間が下し、決めた結果を1本の正式仕様に書き戻させました。実装はIssue単位でClaude Codeに任せ、レビューとマージは必ず別の人間が行っています。作品の中では、願いの言い換え・追加の質問・逆算ツリー・次の一歩の提案をAIの担当にしていますが、公開版はモック応答で、本物の呼び出しはサーバー側だけに置き、出力を検査してから画面に出す設計です。
```
